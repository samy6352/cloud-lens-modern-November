## 5. Design notes worth knowing

- `resource_counts` and `resource_ranks` are **not** DERIVED_MODULES: rebuilt in full by
  `Warehouse.refresh_serving` after each derived rebuild, stamped (`*_generation` in `meta`, listed in
  `jobs.SERVING_STAMP_KEYS`), withdrawn by `jobs.coherent_rollup`, served only while stamp == ready generation;
  otherwise readers take the original (slower, exact) path.
- `resource_ranks` tables: `resource_subs`, `resource_ids` (rkey ↔ lower(trim(id)), sub, currency; hash index on
  id), `resource_raw` (every raw spelling → rkey), `resource_daily` (day, rkey, skey, currency, cost),
  `resource_rank_periods` (exact (lo, mid, hi) bounds), `resource_ranks`, `resource_rank_totals`. Build 305–430 s,
  ≈3 GB locally.
- `Reader` carries `ranks`, `scoped`, `narrowed` flags; `Reader.rows(sql, limit, params=)` and `Reader.execute`.
- **Shared-DB trap:** v2 (8100) and v3 (8101) share `cloudlens`. When either publishes a generation the other's
  startup does a full derived rebuild (15–40 min) and v3 then rebuilds `resource_ranks` (~5–7 min). Check
  `pg_stat_activity` before benchmarking.

## 7. S2 in one paragraph (ADR-3 has the why)

No `export_jobs` table: `app/bootstrap.py` approves the **existing** Cost-data pipeline unattended
(`cost_data` → one `focus-setup` job → `focus_workflow.step`). Flag `CLOUDLENS_MANAGED_EXPORTS=true` (installer sets
it) → hourly pass under a `bootstrap:lease`: paged `/subscriptions`, self-check (denied export role → exact
`az role assignment create` command, subscription skipped), managed 13-month horizon (`cost_data.managed_history`),
create + launch. Step order: newest month first, round-robin; cap `CLOUDLENS_EXPORT_CONCURRENCY` (8) enforced in
`focus_workflow.claim_run`; a 429 holds **all** new runs until `max(Retry-After, 60·2ⁿ⁻¹ s)` passes. Status:
`meta` key `bootstrap:status`; grid `GET /api/cost-data/progress`; "Check now" `POST /api/cost-data/bootstrap`.
Exports are Parquet+Snappy FOCUS 1.0r2; loader bounds a Parquet file at 1 GiB and each decoded batch at 64 MB.

## 9. Rules that bite

1. Never edit source while pytest runs (tests read/exec source).
2. Big builds: `CREATE TABLE AS`, not `INSERT … SELECT` (parallelism).
3. Benchmark real results, not `SELECT count(*) FROM (…)`; profile before choosing a fix.
4. Fixes must be generic (work through ingest/derived rebuild on live customer data), not tuned to the HDFC demo.
5. One commit per task, with the `Co-authored-by: Copilot` trailer; update `plan.md` §12 and this file with it.
6. DB collation is `English_India.1252` (libc): text sorts/`lower()` cost µs per row — group/sort on ints or
   `COLLATE "C"` columns; a `COLLATE "C"` expression cannot use a default-collation index (and vice versa).
7. Some tests match source text (e.g. `tests/test_visuals.py`, `tests/test_refresh.py` checks
   `await reader.get(b["name"])` in `exports.py`); refactors can trip them — compare with §2 before calling a failure new.
8. Reader connections are autocommit: a failed statement does not poison the next one.
9. `jobs.run` holds one deployment-wide lease: jobs never step concurrently, so one job must carry every
   subscription (per-subscription jobs would serialise the whole backfill).
10. pytest needs its cache plugin here (the root `conftest.py` uses `config.cache`); don't pass `-p no:cacheprovider`.
